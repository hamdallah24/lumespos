## Architecture

```
src/learning-integration/
├── index.ts                          # Barrel export + auto-registration

├── LearningRegistry.ts               # Dynamic engine registry
├── IntegrationManager.ts             # Discovery, aggregation, normalization
```

## Flow

```
Boot Sequence
    ↓
registerAllEngines()
    ├── LearningRegistry.register(orgLearningAdapter)
    ├── LearningRegistry.register(kpLearningAdapter)
    └── LearningRegistry.register(councilLearningAdapter)
    ↓
IntegrationManager.discover() → [{id, name, version, capabilities}, ...]
IntegrationManager.retrieve({query}) → UnifiedLearningResult[] (aggregated from all)
IntegrationManager.ingest({content}) → count (fans out to all)
IntegrationManager.runMaintenance() → [{engine, actions, details}, ...]
IntegrationManager.health() → [{engine, status}, ...]
```

## Migration Notes

Existing code is unaffected. The Learning Integration Foundation is purely additive:

1. **Executives** continue using `memoryProvider.read()` — no changes needed
2. **Existing schedulers** continue working — new `IntegrationManager.runMaintenance()` runs alongside them
3. **No existing imports broken** — all public APIs preserved
4. **New learning engines** can be added by creating an adapter and calling `LearningRegistry.register()`
5. **`registerAllEngines()` is idempotent** — safe to call multiple times during boot
