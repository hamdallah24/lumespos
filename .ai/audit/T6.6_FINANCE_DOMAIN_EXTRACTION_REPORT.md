## Finance Domain Specification

### Domain: `finance`

**Tools used:** `get_sales_summary`, `get_expenses`, `get_top_products`

**Computed fields:**
| Field | Formula | Description |
|-------|---------|-------------|
| `revenue` | From `get_sales_summary` | Total sales amount |
| `totalOrders` | From `get_sales_summary` | Number of transactions |
| `averageOrderValue` | `revenue / totalOrders` | Average spend per order |
| `totalExpenses` | From `get_expenses` | Total expense amount |
| `grossProfit` | `revenue - totalExpenses` | Gross profit |
| `grossMargin` | `(grossProfit / revenue) * 100` | Profit margin percentage |
| `period` | From query | Time period |
| `branchId` | From query | Branch scope |

### Cache Configuration

| Domain | Default TTL | Rationale |
|--------|-------------|-----------|
| sales | 30s | Fast-changing |
| inventory | 60s | Moderate change |
| products | 120s | Slow-changing |
| expenses | 60s | Moderate change |
| branches | 300s (5 min) | Rarely changes |
| finance | 30s | Computed from sales + expenses |
| missions | 30s | Fast-changing |

## Ready for CFO Migration

The Finance domain is now a **first-class domain** inside `OperationalTruthProvider`. CFO migration will:

```
CFO.getFinancialOverview()
  └── OperationalTruthProvider.getOperationalContext({domains:["finance"]})
        └── OperationalContext.finance { revenue, profit, margin, ... }
              └── CFO reason about financial data
```

No direct `executeOperation` calls.
No direct `KnowledgeProvider` calls for financial data.
Same architecture pattern as COO.
