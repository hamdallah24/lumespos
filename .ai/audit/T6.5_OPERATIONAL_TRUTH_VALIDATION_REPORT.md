## Phase 3 — Contract Stability Audit

### OperationalContext Specification v1

```typescript
interface OperationalContext {
  // ── Sales Domain ──
  todaySales?: {                    // optional — missing if tool fails or no sales data
    total: number;                  // Required if present — total revenue in IDR
    count: number;                  // Required if present — number of transactions
    period: string;                 // Required if present — "today", "yesterday", etc.
    branchId: number;               // Required if present — branch scope
  };
  topProducts?: {                   // optional — missing if tool fails
    name: string;                   // Required if present — product name
    sold: number;                   // Required if present — quantity sold
    revenue: number;                // Required — currently always 0 (BUG: not populated)
  }[];

  // ── Inventory Domain ──
  inventory?: {                     // optional
    itemType: string;               // "BAHAN" | "SETENGAH JADI"
    items: { name: string; stock: number; unit: string }[];
  }[];
  lowStock?: {                      // derived from inventory (stock <= 5)
    name: string;                   // item name
    stock: number;                  // current stock level
    unit: string;                   // measurement unit
    critical: boolean;              // true when stock === 0
  }[];

  // ── Products Domain ──
  products?: {                      // optional
    name: string;                   // product name
    price: string;                  // price as string (Rp formatted)
    isActive: boolean;              // product status
    variants: { name: string; price: string }[];
  }[];

  // ── Expenses Domain ──
  expenses?: {                      // optional
    total: number;                  // total expense amount
    count: number;                  // number of expense transactions
    period: string;                 // NOT in return (BUG: period not forwarded)
  };

  // ── Branch Domain ──
  branches?: {                      // optional
    id: number;                     // branch ID
    name: string;                   // branch name
    location?: string;              // optional location
  }[];

  // ── Mission Domain ──
  missionProgress?: {               // optional
    planId: string;                 // plan identifier
    name: string;                   // plan name
    percent: number;                // completion percentage
  }[];

  // ── Approval Domain ──
  pendingApprovals?: string[];      // optional — currently always empty

  // ── Metadata ──
  rawTexts: Record<string, string>; // Raw tool output per domain (for debugging)
  timestamp: string;                // ISO timestamp of context generation
  source: "database" | "cache" | "error_fallback";
  confidence: number;               // 0-100 — percent of requested domains resolved
  missingDomains: OperationalDomain[];  // domains that returned no data
  errors: { domain: OperationalDomain; error: string }[];  // tool errors per domain
}
```

### Contract Issues Found

| Issue | Location | Severity | Fix |
|-------|----------|----------|-----|
| `topProducts.revenue` always 0 | parser line 86 | **MEDIUM** | Parse revenue from tool output |
| `todaySales.branchId` not populated | parser line 62-72 | **LOW** | Add branchId to parseSalesSummary |
| `expenses.period` not in return type | parser line 139-146 | **LOW** | Add period to parseExpenses return |
| `source` always "database" even from cache | provider line 242 | **MEDIUM** | Set "cache" when returning cached data |
| `rawTexts` optional in type but always populated | provider line 223 | **LOW** | Make consistent |
| No `version` field | OperationalContext | **LOW** | Add `version: 1` for future schema evolution |

**Verdict: ✅ Contract is stable. 6 minor issues found, none blocking.**

## Phase 7 — Failure Recovery

### Failure Matrix

| Scenario | Tool Behavior | Provider Behavior | Executive Impact |
|----------|--------------|-------------------|------------------|
| PostgreSQL offline | executeOperation throws | `catch` → error logged, domain marked missing | confidence drops, LLM told "data tidak tersedia" |
| Tool timeout | executeOperation throws after timeout | Same as above | Same as above |
| Partial failure (1 of 3 tools) | Some throw, some succeed | Successful data included, failed domain marked missing | confidence drops proportionally |
| Empty result (0 sales today) | Returns "Rp0, 0 transaksi" | Parsed successfully as {total:0, count:0} | LLM says "Rp0" — accurate |
| Schema mismatch (tool returns unexpected format) | Parser returns undefined | domainData stays false, domain marked missing | confidence drops, domain missing |
| All tools fail | All throw | confidence=0, missing=all domains, errors populated | LLM says "Data tidak tersedia" |
| Tool returns "Data tidak tersedia" | String matched | `continue` — domainData stays false | confidence drops |

**Provider NEVER throws.** Every tool call is wrapped in try/catch. Executives always receive a valid `OperationalContext` — never an exception.

**Verdict: ✅ Graceful degradation on all failure modes.**
