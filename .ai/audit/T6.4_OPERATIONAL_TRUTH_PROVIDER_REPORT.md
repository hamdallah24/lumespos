## 1. Architecture

### Before (T6.3)

```
COO.handleStatus()
  ├── executeOperation("get_sales_summary")       ← direct SQL
  ├── executeOperation("get_inventory_status")    ← direct SQL
  ├── executeOperation("get_products")            ← direct SQL
```

### After (T6.4)

```
COO.handleStatus()
  └── OperationalTruthProvider.getStatusContext()
        ├── inferDomains(query) → minimal tool set
        ├── getOperationalContext(domains)
        │     ├── executeOperation(tool, params)  ← abstracted
        │     ├── parseResults()                  ← normalized
        │     └── buildContext()                  ← with metadata
        └── return OperationalContext
              ├── todaySales, topProducts, inventory
              ├── products, expenses, branches
              ├── missionProgress, pendingApprovals
              ├── timestamp, source, confidence
              └── missingDomains, errors

COO memformat OperationalContext → LLM prompt
```

## 4. Data Flow Diagram

```
User "Penjualan hari ini?"
  ↓
COO.handleStatus(query, branchId)
  ↓
OperationalTruthProvider.getStatusContext(query, branch)
  ├── inferDomains("Penjualan hari ini?")
  │     → ["sales", "inventory", "products", "expenses", "branches", "missions", "approvals"]
  │
  ├── getOperationalContext({domains, branchId, period:"today"})
  │     ├── executeOperation("get_sales_summary", {period:"today"}, branchId)
  │     │     → SQL: SELECT SUM(total), COUNT(*) FROM orders WHERE ... AND status='completed'
  │     │     → parseSalesSummary() → {total: 0, count: 0}
  │     │
  │     ├── executeOperation("get_top_products", {limit:5}, branchId)
  │     │     → SQL: SELECT productName, SUM(quantity), SUM(subtotal) FROM order_items
  │     │     → parseTopProducts() → [{name:"Matcha Latte", sold:81}, ...]
  │     │
  │     ├── executeOperation("get_inventory_status", {}, branchId)
  │     │     → SQL: inventory query via listInventoryForBranch()
  │     │     → parseInventory() → [{itemType:"BAHAN", items:[...]}]
  │     │
  │     ├── executeOperation("get_products", {}, branchId)
  │     │     → SQL: SELECT name, price, isActive, variants FROM products
  │     │     → parseProducts() → [{name:"Kopi Susu", price:"7000", ...}]
  │     │
  │     ├── executeOperation("get_expenses", {period:"today"}, branchId)
  │     │     → SQL: SELECT SUM(amount), COUNT(*) FROM expenses
  │     │     → parseExpenses() → {total: 0, count: 0}
  │     │
  │     ├── executeOperation("list_branches", {}, branchId)
  │     │     → SQL: SELECT id, name, location FROM branches
  │     │     → 5 branches returned
  │     │
  │     └── buildContext(data, domains, errors, missing)
  │           → OperationalContext with all data + metadata
  │
  └── COO formats OperationalContext → LLM prompt
        → LLM narrates, never creates data
```

## 5. Provider Interface Specification

```typescript
interface OperationalTruthProvider {
  // Smart domain inference from natural language query
  inferDomains(query: string): OperationalDomain[];

  // Get operational context for specific domains
  getOperationalContext(query: OperationalQuery): Promise<OperationalContext>;

  // Quick context for status queries (infers domains automatically)
  getStatusContext(query: string, branchId?: number): Promise<OperationalContext>;

  // Cache management
  clearCache(): void;
  getCacheStats(): { size: number; keys: string[] };
}

interface OperationalContext {
  todaySales?: { total: number; count: number; period: string; branchId: number };
  topProducts?: { name: string; sold: number; revenue: number }[];
  inventory?: { itemType: string; items: { name: string; stock: number; unit: string }[] }[];
  lowStock?: { name: string; stock: number; unit: string; critical: boolean }[];
  products?: { name: string; price: string; isActive: boolean; variants: [...] }[];
  expenses?: { total: number; count: number; period: string };
  branches?: { id: number; name: string; location?: string }[];
  pendingApprovals?: string[];
  missionProgress?: { planId: string; name: string; percent: number }[];
  rawTexts: Record<string, string>;
  timestamp: string;
  source: "database" | "cache" | "error_fallback";
  confidence: number;
  missingDomains: OperationalDomain[];
  errors: { domain: OperationalDomain; error: string }[];
}
```

## 10. Risk Assessment

| Risk | Level | Mitigation |
|------|-------|------------|
| Cache serves stale data | **LOW** | 30s TTL; automatic expiry |
| Tool failure mid-chain | **LOW** | Each tool wrapped in try/catch; errors in `errors[]` array |
| Parser regex mismatch | **LOW** | Tested with actual VPS data; rawTexts fallback available |
| Domain inference wrong | **LOW** | Falls back to all domains for status queries; keyword matching for targeted |
