# Knowledge Classification

**Version:** 1.0.0  
**Status:** STABLE  

Defines the classification dimensions for ALL knowledge in EKS.

---

## Classification Dimensions

Every knowledge item is classified along 5 orthogonal dimensions:

1. **Immutability** — Can this knowledge change?
2. **Source** — Where does this knowledge come from?
3. **Validation** — How validated is this knowledge?
4. **Persistence** — How long does this knowledge live?
5. **Access** — Who can access this knowledge?

---

## Dimension 1: Immutability

| Class | Symbol | Definition | Examples |
|-------|--------|------------|----------|
| **Immutable** | I | Never changes after creation. Append-only. | Audit logs, knowledge episodes, ADRs (after ACCEPTED) |
| **Stable** | S | Changes rarely, through formal process. | Foundation directives, Constitution, EROS documents |
| **Dynamic** | D | Changes regularly based on new data. | Business metrics, inventory levels, sales data |
| **Ephemeral** | E | Changes every session or request. | Conversation context, working memory, session state |

---

## Dimension 2: Source

| Class | Symbol | Definition | Confidence Weight |
|-------|--------|------------|-------------------|
| **Runtime Knowledge** | R | Generated by EIOS Runtime Core (pipeline metrics, health, audit) | HIGH (0.30) |
| **Organization Knowledge** | O | Generated by Organization Layer (governance, compliance, reputation) | HIGH (0.25) |
| **Business Knowledge** | B | Generated by business operations (sales, inventory, products) | HIGH (0.25) |
| **Executive Knowledge** | E | Generated by executive decisions and actions | MEDIUM (0.15) |
| **Temporary Knowledge** | T | Session-scoped, user conversation context | LOW (0.05) |
| **Conversation Knowledge** | C | User interaction history, semantic references | LOW (0.05) |
| **External Knowledge** | X | Sourced from outside the system (market, research) | VARIABLE |
| **RAG Knowledge** | G | Retrieved from external RAG/document sources | MEDIUM (0.15) |
| **Learned Knowledge** | L | Synthesized by learning engine from experiences | MEDIUM-HIGH (0.20) |
| **Historical Knowledge** | H | Past decisions and outcomes (episodes) | HIGH (0.25) |
| **Derived Knowledge** | D | Computed from other knowledge (trends, aggregations) | MEDIUM (0.15) |
| **Validated Knowledge** | V | Confirmed by multiple sources or authority | HIGH (0.30) |

---

## Dimension 3: Validation

| Class | Symbol | Criteria | Examples |
|-------|--------|----------|---------|
| **Raw** | RAW | Single source, unverified | LLM output, single observation |
| **Observed** | OBS | Recorded by one executive | Knowledge episode, execution outcome |
| **Confirmed** | CFM | 5+ successful uses | Knowledge platform pattern promotion |
| **Validated** | VAL | 2+ independent sources | Organizational memory (intelligence) |
| **Active** | ACT | No contradictions, confidence >70 | Knowledge card ACTIVE status |
| **Best Practice** | BP | 20+ sources, confidence >85, importance >70 | Promoted best practice |
| **Foundation Candidate** | FC | 100+ sources, confidence >95, no contradictions | Ready for Foundation promotion |
| **Archived** | ARC | Deprecated or stale | Confidence <30 or unused >30/90d |
| **Retired** | RET | Formally replaced or removed | Superseded documents |

---

## Dimension 4: Persistence

| Class | Symbol | Retention | Examples |
|-------|--------|-----------|----------|
| **Permanent** | PERM | Never deleted | Audit logs, architecture ADRs |
| **Long-term** | LONG | >90 days | Knowledge cards, best practices |
| **Medium-term** | MED | 30-90 days | Learning outcomes, reflections |
| **Short-term** | SHORT | <30 days | Session context, working memory |
| **Transient** | TRANS | Single request | LLM reasoning trace, temporary variables |

---

## Dimension 5: Access

| Class | Symbol | Visibility | Examples |
|-------|--------|------------|----------|
| **Public** | PUB | All executives and users | Product catalog, branch data |
| **Executive** | EXEC | All executives only | Executive decisions, governance audits |
| **Restricted** | RES | Specific executives | CTO: technical architecture; CFO: financial data |
| **Private** | PRIV | Single executive | Executive memory, working memory |
| **System** | SYS | Runtime only | Pipeline metrics, kernel state, health scores |
| **Human** | HUMAN | Founder/operators only | Founder preferences, strategic directives |

---

## Knowledge Classification Matrix

Every knowledge item MUST have a 5-part classification: `{Immutability}:{Source}:{Validation}:{Persistence}:{Access}`

### Examples

| Knowledge Item | Classification | Meaning |
|---------------|---------------|---------|
| Architecture ADR-001 | I:R:VAL:PERM:SYS | Immutable, Runtime, Validated, Permanent, System |
| Product Catalog | D:B:ACT:LONG:PUB | Dynamic, Business, Active, Long-term, Public |
| CEO Decision Episode | I:E:OBS:PERM:EXEC | Immutable, Executive, Observed, Permanent, Executive |
| Conversation History | E:C:RAW:TRANS:PRIV | Ephemeral, Conversation, Raw, Transient, Private |
| Best Practice SOP | S:E:BP:LONG:EXEC | Stable, Executive, Best Practice, Long-term, Executive |
| Pipeline Health Metric | D:R:RAW:SHORT:SYS | Dynamic, Runtime, Raw, Short-term, System |
| Financial Trend Report | D:D:VAL:MED:EXEC | Dynamic, Derived, Validated, Medium-term, Executive |
| Market Research Data | S:X:RAW:MED:REST | Stable, External, Raw, Medium-term, Restricted |

| Learning Reflection | E:L:OBS:SHORT:PRIV | Ephemeral, Learned, Observed, Short-term, Private |

---

## Classification Rules

1. **Every stored knowledge item** MUST have a 5-part classification
2. **Classification is stored** as part of the knowledge metadata
3. **Classification is immutable** for Immutable knowledge; Dynamic knowledge can be reclassified
4. **Validation upgrades** (RAW → OBS → CFM → VAL → ACT → BP) follow the knowledge lifecycle
5. **Access violations** are enforced by GovernanceProvider at query time
6. **Reclassification** requires CKO approval (knowledge-curation capability)
